### 1. 现状快照与机会分析 (Current State Snapshot & Opportunity Analysis)

*   **当前功能总结：**
    通过对代码的全面分析，我们的`CheatHub`应用目前是一个功能完备的macOS代码片段/命令管理工具。其核心功能模块包括：
    *   **分类管理 (`CategorySidebarView`):** 用户可以创建、重命名、删除、拖拽排序以及“固定”分类。这是一个成熟且用户友好的组织系统。
    *   **命令管理 (`CommandListView`):** 在每个分类下，用户可以增删改查命令，支持将常用命令标记为“快速访问”（isFavorite）。
    *   **核心交互 (`CommandItemView`):** 单击命令即可将其内容复制到剪贴板，这是产品的核心价值闭环。
    *   **数据操作 (`CommandViewModel`, `CategoryViewModel`):** 强大的视图模型层，通过CoreData实现了所有数据的持久化、导入/导出(JSON)和UI状态管理。
    *   **用户体验:** 整体UI/UX设计精良，使用了现代化的SwiftUI视图和组件，如磨砂背景、拖拽交互、上下文菜单等。

*   **潜在机会识别：**
    当前产品是一个优秀的**主动型**工具——用户必须预先知道自己需要什么，并手动录入。分析全局目标后，一个巨大的机会浮现出来：将产品扩展为一个**被动型+主动型**的混合工具。
    *   **最大的差距 (The Core Gap):** 代码库显示，应用的所有功能都围绕着其内部存储的`Command`实体。它对系统剪贴板的操作是单向的（写入），完全没有利用到用户日常工作中产生的大量、高价值的临时数据（读取）。
    *   **最低垂的果实 (Low-hanging Fruits):**
        1.  **剪贴板历史记录:** 这是从“主动”到“被动”最自然的一步。我们已经拥有一个完美的列表视图(`CommandListView`)来展示“文本片段”，也拥有一个剪贴板管理器(`ClipboardManager`)。将这两者结合，去捕获系统剪贴板内容，是成本最低、价值最高的扩展。
        2.  **统一的入口:** `CategorySidebarView`的结构非常适合增加一个新的、固定的功能入口，比如“剪贴板历史”，使其与用户手动创建的分类并存，但又明显区分。
        3.  **复用UI模式:** 展示剪贴板历史的界面几乎可以完全复用`CommandListView`的布局和交互逻辑（列表、点击复制），这极大地降低了开发成本。

### 2. 推荐的“N+1”核心目标 (Recommended "N+1" Core Objective)

*   **目标宣言 (Objective Statement):**
    **为应用增加一个自动记录文本剪贴板历史的核心功能，并提供一个专门的视图让用户可以方便地浏览和复用这些历史记录。**

*   **价值主张 (Value Proposition):**
    此目标将极大地扩展产品的核心价值。它解决了用户一个非常普遍的痛点：“我刚刚复制了什么？”，将应用从一个“偶尔使用的查询工具”转变为一个“时刻在后台提供价值的日常助手”。这将显著提高用户的日活跃度和对产品的依赖性，是实现顶层愿景（成为用户的命令和剪贴板管理中心）最关键的第一步。

### 3. 核心决策点分析 (Key Decision Points Analysis)

#### 数据与模型 (Data & Model)
-   **[决策点]:** 如何存储剪贴板历史数据？
    -   **[结论]:** 建议在CoreData中创建一个全新的实体，例如`ClipboardItem`。
    -   **[分析与理由]:** 虽然可以尝试复用`Command`实体，但这会造成概念混淆和长期维护的困难（例如，剪贴板历史有自动过期的业务规则，而`Command`没有）。创建一个独立的`ClipboardItem`实体（包含`content: String`, `createdAt: Date`, `type: String`等属性）可以清晰地将两种数据分离开，使得未来的功能扩展（如不同的保留策略、支持图片等）更为简单和安全。

#### 功能范围 (Feature Scope)
-   **[决策点]:** 在此增量中，我们应该同时支持文本和图片历史，还是先专注其一？
    -   **[结论]:** 强烈建议此“N+1”增量**仅支持文本历史记录**。
    -   **[分析与理由]:** 当前应用的核心是处理文本片段。优先实现文本历史记录，可以完美复用现有的UI范式（如`CommandItemView`的展示逻辑）和交互模型（点击复制文本），能够最快速地交付核心价值。处理图片会引入新的复杂性：如何在CoreData中高效存储图片数据、如何设计新的UI来展示图片预览、点击图片应执行何种操作（复制图片？保存到文件？）。将图片支持作为后续的“N+2”目标，更符合敏捷开发的迭代原则。

#### 核心技术实现 (Technical Implementation)
-   **[决策点]:** 如何实现对系统剪贴板的监控？
    -   **[结论]:** 实现一个基于定时器（Timer）的后台轮询服务。
    -   **[分析与理由]:** 这是实现该功能的技术核心。我们需要一个服务，在应用运行时（即便在后台）也能工作。一个每隔1-2秒检查一次`NSPasteboard`变化的`Timer`是实现此功能最直接且可靠的方式。这个服务需要：1) 读取剪贴板内容；2) 与最近一次保存的历史记录进行比对，避免重复存储；3) 如果内容是新的文本，则创建一个`ClipboardItem`并存入CoreData。

#### 用户体验与界面 (UX & UI)
-   **[决策点]:** 用户应该如何访问剪贴板历史？
    -   **[结论]:** 在`CategorySidebarView`的分类列表最顶部，增加一个固定的、不可删除的“剪贴板”入口。
    -   **[分析与理由]:** 这完全符合用户提供的愿景。代码分析显示，`CategorySidebarView`中已经存在一个“欢迎页”的特殊入口，它通过设置`categoryViewModel.selectedCategory = nil`来工作。我们可以借鉴这种模式，创建一个新的“剪贴板”按钮。点击它时，可以设置一个特定的状态，让`ContentView`显示一个全新的`ClipboardHistoryView`，而不是`CommandListView`或`WelcomeView`。这使得功能入口清晰、一致，且与用户现有的心智模型相符。

### 4. 产品决策与目标指令书 (草案) (Draft of Product Decision & Goal Mandate)

*   **用户故事 (User Story):**
    *   `AS A` (作为一名) 经常使用复制/粘贴的Mac用户
    *   `I WANT TO` (我希望能够) 让CheatHub自动记录我复制过的所有文本内容
    *   `SO THAT` (以便我能) 在需要时轻松找到并重新使用它们，即使我已经复制了新的内容。

*   **验收标准 (Acceptance Criteria):**
    *   **GIVEN** 应用正在运行
    *   **WHEN** 我在系统中的任何地方复制一段新的文本
    *   **THEN** 这段文本应被自动保存到剪贴板历史中，并显示在“剪贴板”视图的顶部。

    *   **GIVEN** 我正在“剪贴板”视图中浏览历史记录
    *   **WHEN** 我单击任意一条历史记录项
    *   **THEN** 该项的文本内容应被复制到系统剪贴板，并弹出一个“已复制”的提示（复用现有`CopyToastView`）。

    *   **GIVEN** 我连续多次复制了完全相同的文本内容
    *   **WHEN** 我查看剪贴板历史
    *   **THEN** 历史记录中只应保存一条该文本的记录，以避免冗余。

    *   **GIVEN** 一条剪贴板历史记录的创建时间已经超过7天
    *   **WHEN** 应用执行例行清理任务（例如，在启动时检查）
    *   **THEN** 该条过期记录应被自动从数据库中删除。

    *   **GIVEN** `CategorySidebarView`被显示
    *   **THEN** 列表顶部必须包含一个固定的“剪贴板”入口，位于“欢迎页”和所有用户分类之上。

    *   **GIVEN** 我复制的是一张图片或文件，而非纯文本
    *   **WHEN** 我查看剪贴板历史
    *   **THEN** 这条记录不应被保存。

*   **战略约束与业务规则 (Strategic Constraints & Business Rules):**
    *   **数据保留策略:** 剪贴板历史记录默认在数据库中保留7天，之后自动删除。
    *   **监控机制:** 剪贴板内容的轮询检查间隔应设置为一个合理的数值（例如，2秒），以平衡实时性和性能开销。
    *   **范围限制:** 此增量明确只支持纯文本（`public.utf8-plain-text`）的捕获。
    *   **去重逻辑:** 仅当新的剪贴板内容与最新一条历史记录不同时，才进行存储。

### 1. 目标差分析 (Target Gap Analysis)

*   **[观测量] 代码现状评估:** (与上一轮相同) 应用是一个功能完备的主动型命令管理工具，核心数据模型为 `Category` 和 `Command`，使用 `ClipboardManager` 进行单向写入。

*   **[目标量] 需求本质解读:**
    核心目标是为应用增加一个**自动、持续**的剪贴板历史记录功能。基于您的反馈，需求澄清并细化为：
    1.  **功能范围**: 本次迭代(`N+1`)将专注于实现**纯文本**历史记录，但数据模型和UI需为未来(`N+2`)支持图片等**媒体类型**做好准备。
    2.  **UI呈现**:
        *   侧边栏固定入口文案为“**剪贴板**”。
        *   历史视图标题为“**剪贴板**”。
        *   列表项需明确标识内容类型（本次迭代统一为“文本”）。
    3.  **核心行为**:
        *   应用运行时**持续监控**剪贴板，不因前/后台状态而中断。
        *   对连续重复内容进行去重。
        *   数据自动保留7天后清理。
        *   历史列表应**近实时更新**。

*   **[目标差] 核心矛盾分析:**
    弥合目标差的关键在于：
    1.  **监控与性能**: 需要一个高效、低功耗的后台监控机制，使用`NSPasteboard.changeCount`避免无效轮询。
    2.  **数据与架构**: 必须引入一个**可扩展的**`ClipboardItem`数据模型，并使用独立的后台`NSManagedObjectContext`进行写入，避免主线程UI争用。
    3.  **UI响应**: 必须建立一个从后台数据变更到前台UI自动刷新的响应式数据流，使用`NotificationCenter`或`@FetchRequest`。
    4.  **UX兼容性**: 必须在引入新功能入口的同时，**完整保留**现有分类列表的高亮、键盘导航等交互体验。

### 2. 兼容性分析 (Compatibility Analysis)

此轮修订方案将通过更优的架构实践，确保与现有系统的精细化兼容：

1.  **数据层接驳**: 在`cheatsheet.xcdatamodel`中新增`ClipboardItem`实体，包含`content: String`, `createdAt: Date`, `type: String`, `data: Data?`。`type`和`data`字段为未来支持媒体类型预留，本次不写入`data`。这与现有实体完全解耦。
2.  **服务层接驳**: `ClipboardMonitor`将使用由`PersistenceController`创建的**私有后台上下文**(`newBackgroundContext`)进行所有数据库写入操作，彻底隔离后台采集与前台UI。它将通过依赖注入`PasteboardReading`协议实现，增强了可测试性。
3.  **UI层接驳**:
    *   **`ContentView` & `CategorySidebarView`**: 恢复`List(selection:)`机制，并建立`categoryViewModel.selectedCategory`与`mainContentState`之间的双向同步。这确保了在添加新视图状态的同时，原有列表交互（高亮、键盘导航）**无任何功能退化**。
    *   **`ClipboardHistoryViewModel`**: 将不再主动`fetch`，而是通过订阅`NSManagedObjectContext.didSaveObjectsNotification`来接收后台上下文的变更通知，并通过`mergeChanges`更新其`viewContext`，触发UI自动刷新。
    *   **文案与视觉**: 所有面向用户的文案（侧边栏、标题）将统一为“剪贴板”。列表项将增加“文本”徽章，符合UI要求。

### 3. 蓝图：技术方案 (Blueprint: Technical Solution)

1.  **扩展`ClipboardItem`数据模型**:
    *   在`xcdatamodel`中为`ClipboardItem`实体增加`type: String`和`data: Data?`（可选）属性。
    *   更新`ClipboardItem+Extensions.swift`的便利构造器，默认设置`type = "text"`。

2.  **重构`ClipboardMonitor`监控服务**:
    *   创建`PasteboardReading.swift`协议，抽象`NSPasteboard`的`changeCount`和`string(forType:)`等接口。
    *   `ClipboardMonitor`将依赖注入`PasteboardReading`协议和**后台`NSManagedObjectContext`**。
    *   监控逻辑改为基于`changeCount`，只有在`changeCount`变化时才读取剪贴板内容，极大降低性能开销。
    *   将**数据清理逻辑**（`cleanupOldItems`）从ViewModel移至`ClipboardMonitor`的初始化阶段，确保每次应用启动时都在后台执行一次清理。

3.  **优化`ClipboardHistoryViewModel`**:
    *   在`init`方法中，注册监听来自**后台上下文**的`NSManagedObjectContext.didSaveObjectsNotification`。
    *   在收到通知后，调用`viewContext.mergeChanges(fromContextDidSave:)`，并触发`fetchItems()`来刷新`@Published`的`items`数组，从而驱动UI近实时更新。

4.  **恢复并增强UI导航**:
    *   在`CategorySidebarView`中，恢复`List(selection: $categoryViewModel.selectedCategory)`和行视图的`.tag(category)`。
    *   在`ContentView`中，使用两个`.onChange`修饰符创建`selectedCategory`与`mainContentState`之间的双向绑定，确保无论哪个状态变化，另一个都会同步。
    *   比较`MainContentState`中的`Category`时，使用更稳定的`objectID`。

5.  **代码质量与可测试性**:
    *   统一所有`NSSortDescriptor`为类型安全的`keyPath:`写法。
    *   修复`Persistence.swift`中的预览数据，使其同步创建且时间戳不同。
    *   在`cheatsheetApp`的生命周期中，确保`ClipboardMonitor`在应用终止前被正确停止。

// cheatsheet/Utils/ClipboardMonitor.swift
// [修改]
import AppKit
import CoreData

class ClipboardMonitor {
    private let context: NSManagedObjectContext
    private let pasteboard: PasteboardReading
    private var timer: Timer?
    private var lastCopiedValue: String?
    private var lastChangeCount: Int
    
    init(context: NSManagedObjectContext, pasteboard: PasteboardReading) {
        self.context = context
        self.pasteboard = pasteboard
        self.lastChangeCount = pasteboard.changeCount
        
        // Run cleanup on initialization in the background
        cleanupOldItems()
        fetchLastItem()
    }

    func startMonitoring() {
        timer = Timer.scheduledTimer(withTimeInterval: 1.0, repeats: true) { [weak self] _ in
            self?.checkClipboard()
        }
    }

    func stopMonitoring() {
        timer?.invalidate()
        timer = nil
    }

    private func fetchLastItem() {
        context.perform {
            let request: NSFetchRequest<ClipboardItem> = ClipboardItem.fetchRequest()
            request.sortDescriptors = [NSSortDescriptor(keyPath: \ClipboardItem.createdAt, ascending: false)]
            request.fetchLimit = 1
            
            do {
                let lastItem = try self.context.fetch(request).first
                self.lastCopiedValue = lastItem?.content
            } catch {
                print("❌ Error fetching last clipboard item: \(error)")
            }
        }
    }

    private func checkClipboard() {
        guard pasteboard.changeCount != lastChangeCount else { return }
        lastChangeCount = pasteboard.changeCount
        
        guard let newText = pasteboard.string(forType: .string),
              !newText.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty,
              newText != lastCopiedValue else {
            return
        }
        
        lastCopiedValue = newText
        
        context.perform {
            _ = ClipboardItem(context: self.context, content: newText)
            print("✅ ClipboardMonitor: Saved new item - \(newText.prefix(30))")
            
            do {
                try self.context.save()
            } catch {
                print("❌ Error saving clipboard item: \(error)")
            }
        }
    }
    
    private func cleanupOldItems() {
        context.perform {
            let sevenDaysAgo = Calendar.current.date(byAdding: .day, value: -7, to: Date())!
            let fetchRequest: NSFetchRequest<ClipboardItem> = ClipboardItem.fetchRequest()
            fetchRequest.predicate = NSPredicate(format: "createdAt < %@", sevenDaysAgo as NSDate)
            
            do {
                let itemsToDelete = try self.context.fetch(fetchRequest)
                if !itemsToDelete.isEmpty {
                    for item in itemsToDelete {
                        self.context.delete(item)
                    }
                    try self.context.save()
                    print("✅ ClipboardMonitor: Cleaned up \(itemsToDelete.count) items older than 7 days.")
                }
            } catch {
                print("❌ Error cleaning up old clipboard items: \(error.localizedDescription)")
            }
        }
    }
}

// cheatsheet/Models/ViewModels/ClipboardHistoryViewModel.swift
// [修改]
import Foundation
import CoreData
import SwiftUI

class ClipboardHistoryViewModel: ObservableObject {
    private let viewContext: NSManagedObjectContext
    
    @Published var items: [ClipboardItem] = []
    @Published var isLoading = false
    @Published var errorMessage: String?
    @Published var showCopyToast = false

    init(context: NSManagedObjectContext) {
        self.viewContext = context
        fetchItems()
        
        NotificationCenter.default.addObserver(
            self,
            selector: #selector(contextDidSave(_:)),
            name: .NSManagedObjectContextDidSave,
            object: nil // Observe saves from any context
        )
    }
    
    @objc private func contextDidSave(_ notification: Notification) {
        // We only care about saves from a background context that get merged to the main
        guard let context = notification.object as? NSManagedObjectContext,
              context != viewContext else {
            return
        }
        
        viewContext.perform {
            self.viewContext.mergeChanges(fromContextDidSave: notification)
            self.fetchItems() // Re-fetch to update the UI
        }
    }
    
    func fetchItems() {
        isLoading = true
        let request: NSFetchRequest<ClipboardItem> = ClipboardItem.fetchRequest()
        request.sortDescriptors = [NSSortDescriptor(keyPath: \ClipboardItem.createdAt, ascending: false)]
        
        do {
            items = try viewContext.fetch(request)
        } catch {
            errorMessage = "Failed to fetch clipboard history: \(error.localizedDescription)"
        }
        isLoading = false
    }
    
    func deleteItem(_ item: ClipboardItem) {
        viewContext.perform {
            self.viewContext.delete(item)
            self.saveContext()
            DispatchQueue.main.async {
                if let index = self.items.firstIndex(of: item) {
                    self.items.remove(at: index)
                }
            }
        }
    }
    
    func copyItem(_ item: ClipboardItem) {
        guard let content = item.content else { return }
        let success = ClipboardManager.shared.copy(content)
        if success {
            showCopyToast = true
            DispatchQueue.main.asyncAfter(deadline: .now() + 2) {
                self.showCopyToast = false
            }
        }
    }

    private func saveContext() {
        do {
            try viewContext.save()
            errorMessage = nil
        } catch {
            errorMessage = "Save failed: \(error.localizedDescription)"
        }
    }
}
